# HTML TALK

使用 HTML 作为表达输出工具。 HTML 相比txt、md有更易理解、用户友好的表达形式，应发挥这一点。

## 1. 机制

- 首波定路径：用户指定 > 默认 `~/share1/research-xxxx.html`。
- 首波创建html文件：后续除非用户显式指定，否则都在已有的html的基础上 **追加** 章节。不重写已有内容。追加时需要更新目录链接。
- 每轮（包括首轮）都应有可跳转的目录。
- html默认浅色主题。

## 2. 表达原则

1. **多图少文** —— 能用图示说清的不写段落。但不为凑图硬画，纯结论用文字。
2. **一眼能懂** —— 读者看到一个图/一段话的前 2 秒应该知道你在说什么、结论是什么方向。不要让人读完全部细节才知道 yes or no。
3. **帮建心智模型** —— 图件的目的是让读者脑子里形成一个可复用的结构（层次/流程/对比），不是展示你查了多少代码。
4. **降低理解门槛** —— 形式服从内容。该用 emoji 消歧就用，该用代码块就用代码块，该用流图就用流图，别拘泥于固定版式。


## 3. 证据纪律

- 非显而易见的结论内联 `<span class="path">file:line</span>`，行号必须真实, 文件第一次出现时给绝对路径。
- 无源码证据的结论不得伪装成事实。推断就说推断，不确定就说不确定。

## 4. 交付

- 写进草稿纸后，对话里只回一句话总结 + 路径，不粘贴正文。
